Tree — core#

Core node types: base class, leaves container, unary, binary, and n-ary nodes, plus tools for inspecting a tree (subtree views and Mermaid tree diagrams).

class Node#
#include <node.h>

Base class for all nodes in the tree.

Every concrete node must implement these pure virtual methods:

  • evaluate_impl(double x, double y, double z): the signed distance at a point (called by evaluate()).

  • prepare_bounding_box(): computes the authored bounding box (called lazily by bounding_box()).

  • clone(): returns a deep copy of the node.

Commonly overridden methods:

  • prepare_impl(): per-sampling setup that needs the voxel size and bandwidth (e.g. Mesh builds its signed distance grid here; the mesh file itself is read in the constructor).

  • sample_impl(): returns the signed distance together with the attribute samples.

  • distance_accuracy() and lipschitz_bound(): the distance guarantee of the subtree.

  • diagram_label(), diagram_family(), properties(), child_nodes(): metadata for diagrams and UIs.

Warning

You must call prepare() on the root node (and thus the whole tree) before calling evaluate(), sample(), is_in_bbox(), gradient(), or snap(). Behavior is undefined otherwise. Methods that only read the authored tree, such as bounding_box(), properties(), child_nodes(), to_diagram() and clone(), are safe before prepare().

Subclassed by Binary, Leaf, N_ary, StochasticFaceLattice, StochasticGraphLattice, Unary

virtual DistanceAccuracy distance_accuracy() const#

How faithfully this node’s value, including its whole subtree, matches the true signed distance.

Composes the node’s own operation with its children’s accuracy, so the root’s answer describes the whole tree. exact and bound promise that the value clamped to the bandwidth is lipschitz_bound()-Lipschitz and that values outside the bounding box are at least the per-axis distance to it (see DistanceAccuracy). Only valid after prepare(); some nodes decide from what prepare() measured. The default is approximate, so a node without an override can only disable optimizations that rely on the guarantee.

Returns:

The accuracy of the subtree rooted at this node.

void prepare(const glm::vec3 &voxel_size, double bandwidth)#

Performs any single-run operations that need to be done before the tree is evaluated.

Must be called once on the root node before calling evaluate(), sample(), is_in_bbox(), gradient(), or snap(). It records the bandwidth, marks the node as prepared and calls prepare_impl(), which composite nodes forward to their children. This is useful for nodes that need the voxel size and bandwidth before evaluation (e.g. Mesh builds its signed distance grid here).

Note

prepare() does not change the bounding box. The bandwidth padding is applied by is_in_bbox().

Parameters:

  • voxel_size – The size of a voxel we plan to sample with

  • bandwidth – The bandwidth of the tree we are sampling

enum class DistanceAccuracy#

How faithfully a node’s value matches the true signed distance to its surface.

The surface (the zero level set) and the sign are always meant to be right; this describes the magnitude away from the surface. Every node reports it for its whole subtree from Node::distance_accuracy(), together with Node::lipschitz_bound().

The guarantee behind exact and bound, for a node prepared with bandwidth T: let G(x) be the returned value clamped to [-T, T], with T where evaluate() returns no value. Then G is L-Lipschitz everywhere (L = lipschitz_bound()), and outside the bounding box every returned value is at least the per-axis distance to the box. So a point with G > 0 has no inside point within G / L of it. Values beyond the bandwidth carry no promise. See tree/core_tree_architecture.md.

Values:

enumerator exact#

A true signed distance (lipschitz_bound() is 1).

enumerator bound#

Never larger in magnitude than lipschitz_bound() times the true distance, within the bandwidth.

enumerator approximate#

Close to the surface, but may over- or under-estimate farther away.

class SubtreeView : public Unary#
#include <subtree_view.h>

A read-only view of one node of a design, with optional ancestor context re-applied.

A design is a tree of nodes. SubtreeView lets tools such as the renderer show part of that tree on its own. With no context the view is exactly the target node’s own result, in the target’s own coordinate frame, so every operation above it is undone.

Two independent options re-apply parts of the path from the root to the target:

  • apply_placement: re-applies every placement ancestor (Translate, Rotate, Scale, Transform, Mirror), so the target sits where it lands in the full design.

  • apply_attributes: re-applies attributes set on ancestors and attribute-process ancestors (AttributeModifier, Blend, Convolve), evaluated where the part sits in the full design. If placement is off, the result is then mapped back onto the target’s own frame.

Booleans and shape modifiers above the target (Union, Difference, Offset, Shell, Tile, …) are never applied: they are the steps a SubtreeView exists to take apart.

The view shares the design’s nodes rather than copying them, and preparing it prepares the target subtree in place. Do not prepare a view and its design concurrently.

virtual DistanceAccuracy distance_accuracy() const override#

How faithfully this node’s value, including its whole subtree, matches the true signed distance.

Composes the node’s own operation with its children’s accuracy, so the root’s answer describes the whole tree. exact and bound promise that the value clamped to the bandwidth is lipschitz_bound()-Lipschitz and that values outside the bounding box are at least the per-axis distance to it (see DistanceAccuracy). Only valid after prepare(); some nodes decide from what prepare()

measured. The default is approximate, so a node without an override can only disable optimizations that rely on the guarantee.

The accuracy of the evaluated chain (the target with any re-applied ancestors). The view returns the chain’s value inside its own box grown by the band. When that box holds the chain’s box (measured by

prepare()), the view is exactly the chain’s field and keeps its accuracy: this is always so with placement or with no context. With attributes but no placement the box is the target’s, which can be smaller than the chain’s (mapping out and back through a Rotate grows the axis-aligned box, and float rounding can move a translated one). The chain’s own promise then says nothing about values between the two boxes, so the view reports approximate, even though the chain’s geometry is the target’s. Approximate also if the chain was last prepared with a narrower band.

Returns:

The accuracy of the subtree rooted at this node.
