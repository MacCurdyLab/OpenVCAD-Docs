class VDBVolume#
#include <vdb_volume.h>

A sampled OpenVDB grid in world space.

Wraps a grid of one value type and samples it with trilinear interpolation (openvdb::tools::BoxSampler) at world-space points. Points away from active voxels read the grid’s background value. Use the aliases FloatVDBVolume, Vec2sVDBVolume, Vec3sVDBVolume and Vec4sVDBVolume.

static inline std::shared_ptr<VDBVolume<GridType>> from_dense(const ValueType *data, size_t nx, size_t ny, size_t nz, const glm::vec3 &voxel_size, const glm::vec3 &origin = glm::vec3(0.0f), float tolerance = 0.0f, bool center = false)#

Build a sparse volume from a dense, row-major block of voxel values.

The block is indexed like a C-ordered numpy array arr[i, j, k] where i runs along world X, j along Y and k along Z, so k is the fastest-varying index in memory. Voxel (i, j, k) is centred at origin + (i * voxel_size.x, j * voxel_size.y, k * voxel_size.z), and sampling at a voxel centre returns that voxel’s value exactly.

Voxels whose value lies within tolerance of zero (every component, for vector grids) are left inactive at the background value of zero, which keeps mostly-empty data sparse in memory. A tolerance of zero drops only exact zeros. With a positive tolerance, an 8x8x8 block whose values all lie within tolerance of each other may be collapsed into a single tile.

The conversion uses openvdb::tools::copyFromDense and runs in parallel; the input is only read.

Parameters:

  • data – Pointer to nx * ny * nz values, k fastest. For vector grids each value is the grid’s packed vector type (e.g. three floats for Vec3sVDBVolume).

  • nx – Number of voxels along X.

  • ny – Number of voxels along Y.

  • nz – Number of voxels along Z.

  • voxel_size – Spacing between voxel centres along X, Y and Z in mm. Each component must be positive.

  • origin – World position of the centre of voxel (0, 0, 0) in mm.

  • tolerance – Values within this distance of zero stay inactive. Must be non-negative.

  • center – If true, place the volume so the full nx * ny * nz block is centred at the origin (origin is then ignored). Unlike the loaders’ center flag this uses the array extent rather than the active voxels, so several fields cut from the same array stay aligned however sparse each one is.

Returns:

A new volume that owns its own sparse copy of the data.

class DICOMLoader#
#include <dicom_loader.h>

Loads a DICOM slice stack into a float volume of Hounsfield Units.

Each stored pixel becomes HU = value * rescale_slope + rescale_intercept. Pixel (column c, row r) of slice i becomes voxel (c, r, i). The volume is placed in world space by the pixel spacing and slice thickness, then by the rigid patient transform read from the first slice, and optionally centred. Only uncompressed pixel data is supported.

class PNGLoader#
#include <png_loader.h>

Loads PNG images into a color volume.

Either extrudes a single image through a depth, or stacks a directory of images along z. Channels are scaled from 0-255 to [0, 1]. Pixel (column c, row r) of slice z becomes voxel (width - 1 - c, r, z), and voxel (i, j, k) is centred at (i, j, k) * voxel_size unless the volume is centred. Every pixel is stored, transparent or black ones included.

class PointSet#
#include <point_set.h>

An immutable set of 3D points with a k-d tree for nearest-neighbour and radius queries.

The storage behind fields built from scattered points (ScatteredInterpolator): data and evaluation stay separate, the way a VDB volume sits behind a FloatAttribute. The tree is an implicit, balanced k-d tree over an index array (median split on the widest axis, small leaves scanned directly), built once in the constructor.

Queries are const and write into caller-supplied buffers, so one PointSet is shared by every clone of the fields built on it and queried from many threads at once.

class ScatteredInterpolator#
#include <scattered_interpolator.h>

Values known at scattered points (one or three components each), interpolated through space.

The evaluation half of a scattered field; the points and their k-d tree live in a shared PointSet. Everything is computed in the constructor and the object is immutable afterwards, so the attributes built on it (ScatteredFloatAttribute, ScatteredVec3Attribute) share one copy across clones and threads.

Methods, with their cost and behaviour away from the data:

  • nearest: each sample finds one neighbour (O(log N)). Far away: the nearest point’s value.

  • inverse_distance: modified Shepard weighting of the k nearest points, w = ((R - d) / (R d))^p, with R the distance to the (k + 1)-th point, so the field stays continuous as the neighbour set changes; with N <= k points, plain 1 / d^p over all of them. Exact at the points, and always between the smallest and largest value. O(log N + k) per sample. Far away: the average of the nearest points.

  • radial_basis with thin_plate_spline: solves a dense (N + 4)^2 system once (O(N^3); about a second for 2,000 points), capped at max_thin_plate_points; each sample sums over every point (O(N)). Smooth, exact at the points (unless smoothing > 0), may overshoot the data range. Far away it follows the fitted linear trend. Coplanar or collinear points fit a lower trend.

  • radial_basis with wendland: a sparse system solved by conjugate gradients, with nonzeros only between points closer than the radius; each sample visits the points within the radius. Scales to large N while the radius holds tens of points. Away from the data it returns to the mean of the values.
