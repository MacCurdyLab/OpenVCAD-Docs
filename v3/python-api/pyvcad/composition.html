Tree — composition nodes#

Composition nodes are non-Leaf nodes that each own one or more child subtrees. They describe how pieces are placed and combined in space: rigid transforms, mirrors, warps and tilings, sums and mixes of fields, constructive solid geometry (union, intersection, difference and bbox variants), offsets and shells.

Use them to assemble and modify designs built from Tree — leaf nodes without duplicating underlying primitives.

class pyvcad.Identity#

A pass-through identity node that implements no transformations or operations of its own.

This node operates identically to the base Unary node. Its primary use case is to act as an attachment point for AttributeModifiers without affecting the global coordinate space of the attributes, which is useful when its child node contains an arbitrary transformation.

class pyvcad.Rotate#

Rotates a child node about the centre of the child’s bounding box by three Euler angles in degrees.

Parameters, always in this order: pitch (about the X axis), yaw (about the Y axis), roll (about the Z axis). The Vec3 constructors pack the same angles as (x, y, z) = (pitch, yaw, roll).

Order: the child is turned by roll about Z first, then by yaw about Y, then by pitch about X, all about the fixed world axes through the pivot. The applied matrix is R = Rx(-pitch) * Ry(-yaw) * Rz(-roll), and a child point c lands at R * (c - pivot) + pivot.

Sign: each angle is negated before it is applied, so a positive angle turns the child clockwise when looking from the positive end of its axis toward the origin (the opposite of the right-hand rule). Rotate(90, 0, 0) sends +Y to -Z; Rotate(0, 90, 0) sends +Z to -X; Rotate(0, 0, 90) sends +X to -Y.

Pivot: the rotation turns about the child’s bounding-box centre (see pivot()), not about the origin. Use Transform to rotate about the origin.

Helpers: Rotate.from_axis_angle(axis, degrees, child) builds a right-hand-rule rotation about any axis, matrix() returns the exact 4x4 that is applied, and pyvcad.alignment_angles(forward, up) computes angles that aim a child’s local axes.

Rotation keeps the child’s signed distance exact.

class pyvcad.Scale#

Scales a child about the origin by positive factors, uniformly or per axis. This node is unary, therefore can only have one child.

Uniform scaling (one factor, or three equal factors) is exact: the child’s signed distance is multiplied by the factor, so a true signed distance field stays a true signed distance field.

Non-uniform scaling (different factors per axis) is allowed but warps the signed distance field, so use it with caution. The node returns a first-order estimate d / |S^-1 n| (d the child’s value, n its unit gradient direction, S = diag(sx, sy, sz)). It is exact on planar faces and accurate near the surface, and always lies between d * min(s) and d * max(s), but it drifts from the true distance far from curved surfaces. Offset, Shell, distance-driven attributes and smooth blends above a non-uniform Scale are therefore approximate. The sign, and so the surface itself, is always exact. A non-uniform scale costs about seven child evaluations per evaluation.

class pyvcad.Transform#

Places a child with a full 4x4 affine matrix in one step. This node is unary, so it may only have one child.

Convention: the matrix is written row by row, as on paper and as NumPy prints it. Points are column vectors and the matrix maps child coordinates to world coordinates, world = M @ [x, y, z, 1], so the translation is the last column. The matrix acts about the origin (unlike Rotate, which turns about the child’s bounding-box centre). Compose the usual way, M = T @ R @ S, to scale first, then rotate, then translate. The bottom row must be [0, 0, 0, 1] and the upper-left 3x3 block must be invertible; reflections are allowed.

Distance: if the 3x3 block is a rotation or reflection times a uniform scale, the signed distance stays exact. Otherwise it stretches space unevenly and warps the signed distance field, so use it with caution: the node returns the first-order estimate d / |A^-T n|, like a non-uniform Scale. It is exact on planar faces and accurate near the surface, but it drifts from the true distance far from curved surfaces, so Offset, Shell, distance-driven attributes and smooth blends above it are approximate. The sign, and so the surface itself, is always exact. preserves_distance() tells which case applies.

Transform.shear() and Transform.shear_matrix() build a shear.

class pyvcad.MappedNode#

Wraps any child node through a CellMap so geometry designed in a flat box follows the curved map. A world point is inverted to logical map coordinates (u, v, w) and the child is evaluated at (u * s_u, v * s_v, w * s_w). With space=’physical’ the scale s is the map’s average millimetres per logical unit, so the child is authored in approximate millimetres inside child_bounds; with space=’logical’ the child is authored in cell units. The returned distance is a first-order Jacobian estimate (child value over the world gradient length): accurate near the surface and safe for meshing within a narrow band, but approximate far from it. The mapped child exists only inside the active map domain.

class pyvcad.Warp#

Deforms space: the child is sampled at g(p), where a map g pulls each world point p back to the child point it came from.

Attributes (pull-back): the child’s attributes are sampled at g(p), so material follows the deformation. coordinate_field() turns the map’s coordinates into fields: ‘child_x’, ‘child_y’ and ‘child_z’ (where a point pulls back to) for every map, plus the map’s own.

Distance accuracy: the surface is exact. The value is the first-order estimate f / |J^T n| (f the child’s value at g(p), J the map’s Jacobian, n the child’s gradient direction): accurate near the surface, approximate far from it, like a MappedNode or a non-uniform Scale. With lipschitz=L, an upper bound on how much g stretches lengths, the value is f / L instead, never larger than the true distance inside the box for an exact child. distance_accuracy() is approximate either way: just outside the box f / L can fall below the distance to the box, so the value jumps where the box ends.

Bounding box: a warp moves material, so a field map needs explicit bounds (the world box that holds the warped child). Built-in deformations work out their own box.

Built-in deformations: Warp.twist(), Warp.taper(), Warp.bend(), Warp.wrap_cylinder() and Warp.wrap_sphere(), whose maps are analytic, so their Jacobians are exact and cheap; and Warp.displace(), which moves material by a displacement field such as a simulation result.
