Volumes#

Volume adapters connect discrete 3D grids (simulation output, CT/MRI, or other VDB-backed data) to OpenVCAD’s continuous sampling model. Instead of baking data into dense meshes, you keep a sparse OpenVDB grid and query it at any world-space point. Sampling uses trilinear interpolation between voxel centers, so fields stay smooth for rendering, slicing, and compilers.

Typical uses include mapping Hounsfield units or bone density to material properties, reusing FEA or fluid fields on printable geometry, and importing artist-authored VDBs from external tools.

Interface you use in Python

  • Typed volumes — FloatVolume, Vec2sVolume, Vec3sVolume, and Vec4sVolume wrap scalar or vector VDB grids. Call sample(x, y, z) for a value, bounding_box() for world-space bounds, and clone() when you need a thread-safe copy for concurrent evaluation.

  • VDB files — Use pyvcad.vdb_loader (load_float_volume, load_vec3s_volume, load_vec4s_volume) to open a named grid from a .vdb file, optionally centered on the origin.

  • PNG images — PNGLoader.FromImage extrudes one image and PNGLoader.FromStack stacks a directory of slices. Depending on the PNGColorMode, as_rgb_volume() returns a Vec3sVolume or as_rgba_volume() a Vec4sVolume with channels in [0, 1].

  • DICOM stacks — DICOMLoader reads a directory of slices, applies real-world spacing and rescale metadata where available, and builds a scalar FloatVolume (commonly HU). Call as_volume() when you are ready to sample. Slices are stacked in Instance Number (0020,0013) order when every file carries a unique one, and otherwise in natural (digit-aware) filename order, so 1/2/10, 001/002/010 and IMG_0000_0001 style exports all stack correctly. Pass slice_order to force a strategy (pv.DICOMSliceOrder.INSTANCE_NUMBER, SLICE_POSITION or FILENAME) and filename_prefix to ignore a leading part of the filename whose digits should not take part in the ordering.

  • Unstructured result fields — UnstructuredFieldDataset copies TET4 point/connectivity arrays, stores named point- or cell-associated scalar and three-component vector results, and exposes them as ordinary FloatAttribute and Vec3Attribute objects. XDMFFieldLoader provides the same dataset from the supported XDMF 3/HDF5 subset.

  • Scattered points — Values at points with no connectivity (measurements, sensors, point exports) become a field with FloatAttribute.from_points or Vec3Attribute.from_points from NumPy arrays; see the scattered-point fields on the Attributes page.

  • Attributes — A FloatVolume is a continuous field; pass it to FloatAttribute(volume) (or set_volume on an existing FloatAttribute) and attach that attribute to geometry with set_attribute, same as expression-driven fields. Evaluation runs where your solid exists, using the volume’s values inside the part.

Examples#

The patterns below mirror the getting-started discussion of sampled scalar fields: load data, wrap in FloatAttribute, attach to a primitive or mesh.

VDB scalar grid

import pyvcad as pv

vol = pv.vdb_loader.load_float_volume("model.vdb", "density")
bbox_min, bbox_max = vol.bounding_box()
solid = pv.RectPrism.FromMinAndMax(bbox_min, bbox_max)
solid.set_attribute(pv.DefaultAttributes.DENSITY, pv.FloatAttribute(vol))

DICOM series → float volume

import pyvcad as pv

loader = pv.DICOMLoader("path/to/dicom_series")
vol = loader.as_volume()
solid = pv.RectPrism.FromMinAndMax(*vol.bounding_box())
solid.set_attribute(pv.DefaultAttributes.HU, pv.FloatAttribute(vol))

DICOM series with an awkward naming convention

When an export writes filenames such as scan2024_001.dcm, the constant 2024 would otherwise dominate a filename sort. Ignore it with filename_prefix, and force the filename strategy when the files carry no usable Instance Number:

import pyvcad as pv

loader = pv.DICOMLoader(
    "path/to/dicom_series",
    slice_order=pv.DICOMSliceOrder.FILENAME,
    filename_prefix="scan2024_",
)

# Inspect the resolved order without loading any pixel data.
files = pv.sort_dicom_slices(
    pv.collect_dicom_files("path/to/dicom_series"),
    pv.DICOMSliceOrder.FILENAME,
    "scan2024_",
)

Unstructured TET4 result fields#

An unstructured field dataset is data, not geometry. Keep or separately import the OpenVCAD node that should consume the result, then attach a returned attribute to that node:

import numpy as np
import pyvcad as pv

results = pv.UnstructuredFieldDataset.from_tetrahedra(points, cells)
results.add_point_vector("displacement", displacement, units="mm")
results.add_point_scalar(
    "strain_energy_density",
    energy,
    units="mJ/mm^3",
    step_identifier="load-1",
)

energy_attribute = results.float_attribute(
    "strain_energy_density",
    outside="boundary_clamp",
    max_distance=0.8,
)
source_geometry.set_attribute("strain_energy_density", energy_attribute)

Point-associated values are interpolated with TET4 barycentric coordinates. Cell-associated values remain piecewise constant. Coordinates and input values may be contiguous or strided NumPy-compatible float32/float64 arrays; connectivity must use an integer dtype. Construction copies every input array, so later mutation or deletion of the NumPy arrays does not affect the dataset.

Outside behavior is always explicit:

  • "error" is the default and raises when an ordinary attribute is sampled outside the domain. A constant or max_distance supplied with this policy is rejected rather than silently changing its meaning.

  • "constant" requires constant_value; no implicit zero fill is used.

  • "boundary_clamp" projects to the closest point on the outer TET4-domain boundary and requires a finite max_distance. Beyond that band it raises, unless an explicit constant_value is also provided.

Numerical containment tolerance is separate from geometric boundary clamping. Use sample_scalar / sample_vector to inspect one query’s SampleStatus, or coverage to preflight a batch without adding counters to ordinary attribute samples:

report = results.coverage(
    query_points,
    outside="boundary_clamp",
    max_distance=0.8,
    maximum_failures=8,
)
print(report.inside_count, report.boundary_clamped_count, report.outside_count)

Coordinates default to the reference dataset coordinates. transformed uses two deliberately separate matrices: a 4x4 affine matrix maps consuming node positions into dataset positions, and a 3x3 matrix maps stored vector components into consuming coordinates. A displacement field never deforms the domain implicitly. Unit conversion is an explicit matrix scale rather than an effect of the units metadata:

aligned = results.transformed(
    consumer_to_dataset_position,
    stored_to_consumer_vector,
)

max_distance is measured after the position transform, in reference dataset-coordinate units. This keeps its meaning explicit when the transform also performs a model-to-solver unit conversion.

XDMFFieldLoader supports XDMF 3 Uniform grids with TopologyType="Tetrahedron", GeometryType="XYZ", direct HDF-backed topology/geometry/attributes, Center="Node" or Center="Cell", and scalar or three-component vector attributes. Select grid_name when a file contains more than one Uniform grid and optionally select field_names. Temporal or spatial collections, mixed topology, HEX8, inline XML arrays, functions, hyperslabs, tensors, malformed dimensions, and unsupported numeric types fail explicitly; this loader is not a general XDMF implementation.

results = pv.XDMFFieldLoader.load(
    "result.xdmf",
    grid_name="OpenVCADMesh",
    field_names=["displacement", "strain_energy_density"],
)

static from_array(array: typing.Annotated[numpy.typing.ArrayLike, numpy.float32], voxel_size: object, origin: pyvcad.pyvcad.Vec3 = <pyvcad.pyvcad.Vec3 object at 0x106974f70>, tolerance: typing.SupportsFloat | typing.SupportsIndex = 0.0, center: bool = False) → pyvcad.pyvcad.FloatVolume#

Build a float volume from a 3D numpy array.

The array is indexed as array[i, j, k] with i along X, j along Y and k along Z. Voxel (i, j, k) is centred at origin + (i * dx, j * dy, k * dz), so sampling at a voxel centre returns its value exactly and values in between are trilinearly interpolated. Any numeric dtype is accepted and converted to float32; non-contiguous and Fortran-ordered arrays are copied into C order first.

Voxels with abs(value) <= tolerance are left inactive (value 0) so mostly-empty data stays sparse.

Parameters:

  • array (numpy.ndarray) – Array of shape (nx, ny, nz).

  • voxel_size (float | Vec3) – Spacing between voxel centres in mm. A Vec3 gives per-axis spacing.

  • origin (Vec3) – World position of the centre of voxel (0, 0, 0) in mm. Defaults to (0, 0, 0).

  • tolerance (float) – Values within this distance of zero stay inactive. Defaults to 0.0.

  • center (bool) – If True, centres the whole array about the origin (origin is then ignored). This uses the array extent, not the active voxels, so several fields from one dataset stay aligned. Defaults to False.

Returns:

A new volume holding a sparse copy of the data.

Return type:

FloatVolume

Raises:

ValueError – If the array is not 3D, or voxel_size or tolerance are invalid.

Example

>>> import numpy as np
>>> import pyvcad as pv
>>> density = np.random.rand(64, 64, 32)
>>> volume = pv.FloatVolume.from_array(density, pv.Vec3(0.5, 0.5, 1.0), center=True)
>>> attribute = pv.FloatAttribute(volume)

class pyvcad.DICOMLoader#

A loader for DICOM image stacks that converts them to FloatVolume volumes of Hounsfield Units.

Each stored pixel becomes HU = value * rescale_slope + rescale_intercept. The volume is placed by the pixel spacing and slice thickness, then by the patient transform in the first slice, and optionally centred. Only uncompressed pixel data is supported.

Constructor. Loads a DICOM image stack.

Values left at their default are read from the first slice’s metadata.

Parameters:

  • directory (str) – The directory containing the DICOM stack.

  • center (bool, optional) – Whether to center the volume at the origin. Default is False.

  • rescale_slope (float, optional) – The rescale slope to apply to pixel values.

  • rescale_intercept (float, optional) – The rescale intercept to apply to pixel values.

  • slice_thickness (float, optional) – The slice thickness in mm.

  • x_pixel_spacing (float, optional) – The pixel spacing in x direction in mm.

  • y_pixel_spacing (float, optional) – The pixel spacing in y direction in mm.

  • slice_order (DICOMSliceOrder, optional) – How the slice files are ordered into a stack. Defaults to DICOMSliceOrder.AUTO, which sorts by Instance Number (0020,0013) when every file carries a unique one and otherwise falls back to a natural (digit-aware) filename sort.

  • filename_prefix (str, optional) – A literal filename prefix ignored when the order falls back to filenames. Use it when the fixed part of a filename contains digits that must not take part in the ordering, for example scan2024_ in scan2024_001.dcm.

Raises:

class pyvcad.DICOMSliceOrder#

How the slice files of a DICOM series are ordered into a stack.

Members:

AUTO : Sort by Instance Number when every file carries a unique one, otherwise sort by filename.

INSTANCE_NUMBER : Always sort by Instance Number (0020,0013). Raises when the tag is missing or duplicated.

SLICE_POSITION : Sort by the geometric slice position taken from Image Position Patient (0020,0032) or Slice Location (0020,1041). Raises when the position cannot be determined.

FILENAME : Sort by filename only, using a natural (digit-aware) comparison. Reads no metadata.

class pyvcad.PNGLoader#

A loader for PNG image volumes. Supports both single-image extrusion and ordered image stacks.

Channels are scaled from 0-255 to [0, 1]. Pixel (column c, row r) of slice z becomes voxel (width - 1 - c, r, z), centred at (i, j, k) * voxel_size unless the volume is centred. Every pixel is stored, transparent or black ones included.

pyvcad.vdb_loader.save_float_volume(volume: pyvcad.pyvcad.FloatVolume, file_path: str, grid_name: str) → None#

Save a float volume to a VDB file as a single named grid.

Useful for caching volumes built from numpy arrays so they can be reloaded with load_float_volume. The grid keeps its transform, so it reloads at the same world position. Existing files are overwritten.

Parameters:

  • volume (FloatVolume) – The volume to save.

  • file_path (str) – Destination .vdb path.

  • grid_name (str) – Name stored for the grid.

Raises:

  • RuntimeError – If the file cannot be written.

  • ValueError – If grid_name is empty.

Example

>>> volume = pv.FloatVolume.from_array(density, 0.5)
>>> pv.vdb_loader.save_float_volume(volume, 'density.vdb', 'density')
>>> cached = pv.vdb_loader.load_float_volume('density.vdb', 'density')
